# Commerce One

> Commerce One, Inc. was a Pleasanton, California B2B e-commerce software company
> and one of the defining names of the dot-com era. It ceased operating after
> filing for bankruptcy in October 2004. It has no live API, no developer portal
> and no operating developer surface. One technical artifact survives and is still
> publicly downloadable: xCBL, the XML Common Business Library — a royalty-free
> library of XML business documents for global trade.

## Status

- Company status: defunct. Filed bankruptcy October 2004.
- Patent portfolio sold to Novell subsidiary JGR Acquisitions (December 2004, $15.5M);
  remaining assets to ComVest Partners; the Commerce One name acquired by
  Perfect Commerce (February 2006).
- commerceone.com: registered but publishes no DNS A record — does not resolve.
- xcbl.org: LIVE, static archival site, plain HTTP only (no TLS), Microsoft-IIS/10.0.
- Do not expect any authentication, rate limits, SLA, status page or support response.

## What Commerce One built

- MarketSite and the Global Trading Web — B2B e-marketplace and trading network.
- SOX (Schema for Object-Oriented XML) — Commerce One's own schema language,
  which influenced W3C XML Schema and JAXB. Superseded by XSDL in xCBL 4.0.
- xCBL — the XML Common Business Library, the surviving artifact described below.

## xCBL 4.0 — XML Common Business Library

- Home: http://xcbl.org/
- Version 4.0, final release, March 2003. Canonical form: W3C XML Schema (XSDL).
- 44 business documents across 9 namespaces (one shared "core" of reusable types
  plus 8 functional-area namespaces that reference only core, allowing each to be
  versioned independently). Namespace URIs use the rrn:org.xcbl: scheme.
- Initial alignment with OASIS UBL; semantics derived from xCBL 3.5, EDI and RosettaNet.
- Distribution: http://xcbl.org/xcbl40/downloads/xcbl40.zip (1.8 MB, 846 files,
  709 .xsd modules plus sample XML instances). Download is gated by a
  click-through license page, not by credentials.
- License: perpetual, nonexclusive, royalty-free, worldwide right to use, publish,
  copy, modify and distribute, subject to attribution — http://xcbl.org/license.shtml

### Functional areas

- core — reusable component types shared by all other namespaces.
- ordermanagement — Order, ChangeOrder, OrderResponse, OrderStatusRequest,
  OrderStatusResult, OrderConfirmation, OrderConfirmationResponse, OrderRequest.
- preordermanagement — PriceCheckRequest/Result, AvailabilityCheckRequest/Result,
  RequestForQuotation, Quote, AvailabilityToPromise(+Response).
- financial — Invoice, InvoiceResponse, RemittanceAdvice, PaymentRequest,
  PaymentRequestAcknowledgement, FXRateRequest/Response, PaymentStatusRequest/Response.
- materialsmanagement — AdvanceShipmentNotice, GoodsReceipt, PlanningSchedule(+Response),
  ShippingSchedule(+Response), InventoryReport.
- messagemanagement — MessageAcknowledgement, ApplicationResponse, ErrorResponse.
- applicationintegration — Requisition, AccountCheck, GetOrder, GetERPData, GetERPDataResponse.
- catalog — ProductCatalog.
- statisticsandforecasting — TimeSeries, TimeSeriesRequest, TimeSeriesResponse.

### Error model

xCBL is a document-exchange vocabulary, not an HTTP API, so there is no
problem+json surface. Failures are carried as xCBL documents: ErrorResponse
(Code, String, DetailedMessage, SeverityCoded, CategoryCoded, ScopeCoded,
Originator, Role, Pointer) and ApplicationResponse. Enumerated code lists cover
error type (CorrelationError, BusinessError, PayloadError, Informational, Other),
severity (Fatal, Warning, Transient), category (TransportUnavailable,
TransportFailure, AuthenticationFailure, AuthorizationFailure, SignatureFailure,
EncryptionError, StructureError, ContentError, ProcessFailure, Unknown) and
scope (Envelope, Header, Payload, Attachment, NonMessageRelated, Unknown).
